# P7 仪表歌词投放

## 范围

设置 → 仪表投放（实验性）。默认关闭，仅显示在 E28 / Android 9 上。
替换的是原车仪表导航卡片中的地图图片，不是原车音乐卡片，也不是整个仪表。
请先选择原车仪表的导航卡片。充电等原车页面覆盖该卡片时，应用等待原车图片请求。
不要同时运行 OP 或其他占用同一原车小地图接口的投放应用。

保留 Apple Music 在 iPhone 上播放，通过已有 CarPlay/iAP2 Now Playing 订阅接收
歌名、歌手、专辑、时长、播放状态和进度；不开发 iPhone 应用，不登录 Apple Music。
收到进度后使用单调时钟推算位置；暂停冻结，跳转重新校准。
新歌尚未收到自己的进度，或播放中超过 15 秒没有位置变化时，不继续猜测歌词进度。
是否完整收到这些数据，仍需在实际 iPhone / Apple Music 会话中确认。

在线歌词来自 LRCLIB：https://lrclib.net/docs 。查询发送歌曲元数据，不发送音频、
位置、设备标识或认证材料。优先精确匹配标题、歌手、专辑和时长；搜索回退只接收
相同标题/歌手、时长相差不超过两秒的同步歌词，无法确定版本时不随意选择。
只做逐句切换；缺失歌词或进度时显示歌曲信息和等待提示。
车机需要实际互联网连接；iPhone 连车机热点不等于车机可以使用 iPhone 的蜂窝网络。
私有缓存目录最多 50 MB，优先使用缓存。清缓存与关闭在线查询会使旧网络请求失效。
新增“歌词延迟”：所有歌曲统一延后 0–5000 毫秒，每步 50 毫秒，默认 0，立即生效且无需重连。
用于补偿 CarPlay 音频延迟，计算位置 = 播放位置 - 全局歌词延迟。
不按歌曲保存校准值。

## 权限及进程

- 复用已有 INTERNET、ACCESS_NETWORK_STATE 普通权限，无新授权弹窗。
- 需要已开启的本机 ADB 和对 XPlay 自身密钥的调试授权。首次点击“授权并启动通道”。
- 只接受 UID 2000 的 shell，不需要 Root，也不尝试开启关闭中的 adbd。
- shell 需要已有 CAR_VENDOR_EXTENSION 与 REAL_GET_TASKS 权限及可用的小鹏服务接口；
  普通 APK 声明权限不能代替这些检查。
- 不需要定位、通知读取、无障碍、悬浮窗权限。WRITE_SETTINGS 热点授权与仪表通道无关。
- 第一版使用本机 ADB，未增加 Shizuku 依赖。
- shell worker 固定匹配正式包 com.laiqidong.xplay；普通 .hudtest 调试包可编译、查看菜单，
  但不会启动车机投放。实车应使用既有签名车机打包流程。

启动仅加载当前 APK 与车机现有 android.car.jar，不拷贝厂商固件、不开远程命令端口。
图片在进程内存中绘制，压缩为 JPEG，通过双方验证 UID 的本机 abstract socket 传递。
worker 根据原车 Need / Size-w / Size-h / Fps / Format 请求输出，保留图片大小及格式限制；
提交频率上限为 5 fps。歌词变化才重新绘制和压缩，相同图片按原车节奏重复提交。

## 地图交接与恢复

复用固定 MiniMapService 的停止确认、恢复标记和 RESET 绘图表面重建。
取得通道前检查原车生产者已停止；只恢复本通道确实暂停过的服务，不停止整个原车导航。
失去原车图片请求时释放；断开 CarPlay、停止投放或关闭开关时关闭图片 socket。
独立 shell guardian 在 EOF / 超时后尝试恢复，异常恢复标记保留到确认恢复成功。
设置页检查恢复标记，区分“通道已释放”和“恢复未确认”；标记消失仍不等于实车可见地图已恢复。
可选车道条隐藏默认关闭；开启后只写 lane 字段，不改导航模式或车辆控制。
已知新鲜快照尝试恢复，无快照时等待原车后续更新；不能承诺旧蓝条立即重现。

主 Activity 的退到后台、重建和返回不会自行停止投放，生命周期随现有媒体会话。
所有仪表开关和样式变更只修改仪表通道，不重连正在运行的 CarPlay。
手动停止在当前会话内抑制自动重启；重新点击启动或新 CarPlay 会话恢复该策略。
